3. Fundamentos de Cloud Computing

Definição

Entrega de recursos de TI sob demanda pela internet, com pagamento pelo uso (pay-as-you-go).

As 6 Vantagens da Nuvem (decore)

  1. CAPEX → OPEX — paga só pelo que usa (troca custo fixo por variável).
  2. Economia de escala — a AWS compra em massa e repassa preço menor.
  3. Parar de adivinhar capacidade — escala na hora certa.
  4. Velocidade e agilidade — recursos em minutos, não semanas.
  5. Parar de manter data center — infra física é problema da AWS.
  6. Alcance global em minutos — várias regiões no mundo.

Desvantagens / Desafios

Desvantagem Significado
Dependência de internet Sem conexão, sem acesso
Vendor lock-in Dificuldade de migrar de provedor
Custo pode fugir do controle Fácil criar recurso; precisa Budgets/Cost Explorer
Menos controle da infra Não controla hardware/locação física
Responsabilidade compartilhada Segurança na nuvem é sua
Compliance / soberania Dados podem precisar ficar em região específica

Modelos de Implantação

Modelo O que é
Nuvem pública Recursos do provedor, compartilhados
Nuvem privada Infra exclusiva de uma empresa
Híbrida On-premises + nuvem pública
Multi-cloud 2+ provedores (AWS + Azure)

⚠️ Deployment (onde roda) ≠ modelo de serviço (IaaS/PaaS/SaaS).

Elasticidade vs Escalabilidade vs Agilidade

  • Escalabilidade = crescer pra aguentar carga (vertical = VM maior; horizontal = mais VMs).
  • Elasticidade = escalar pra cima e pra baixo automaticamente.
  • Agilidade = rapidez pra criar recursos.

Alta Disponibilidade vs Tolerância a Falhas vs DR

Conceito Significado
Alta Disponibilidade (HA) Continua com mínimo downtime (múltiplas AZs)
Tolerância a falhas Continua sem interrupção nenhuma (mais forte)
Disaster Recovery (DR) Plano pra recuperar após desastre (RTO/RPO)

Hierarquia: DR < HA < Tolerância a falhas.

Well-Architected Framework — 6 Pilares

  1. Excelência operacional — operar e melhorar continuamente.
  2. Segurança — proteger dados e sistemas.
  3. Confiabilidade — recuperar de falhas e garantir disponibilidade.
  4. Eficiência de performance — usar recursos da forma certa.
  5. Otimização de custos — evitar gasto desnecessário.
  6. Sustentabilidade — minimizar impacto ambiental (pilar novo).

Shared Responsibility Model (conceito nº 1)

  • AWS é responsável pela segurança DA nuvem (infra física: data center, hardware, rede, hipervisor).
  • Você é responsável pela segurança NA nuvem (dados, IAM, configuração, SO do EC2, senhas).

Quanto mais "managed" (SaaS > PaaS > IaaS), mais responsabilidade da AWS e menos sua.

Regiões, AZs e Edge Locations

  • Região = área geográfica (ex: us-east-1, sa-east-1 em SP).
  • AZ (Availability Zone) = data centers isolados dentro da região.
  • Edge Location = pontos de cache global (CloudFront, Route 53).

Serviços globais: IAM, Route 53, CloudFront. Regionais: EC2, S3, RDS.

4. Modelos de Serviço (IaaS/PaaS/SaaS)

Modelo Você gerencia Exemplos AWS
IaaS SO, aplicação, dados EC2, EBS, VPC
PaaS Só código e dados Elastic Beanstalk, RDS, Lambda*
SaaS Nada (só configurar) WorkMail, QuickSight

*Lambda = FaaS (Function as a Service), um "PaaS serverless".

Analogia da pizza 🍕: - IaaS = compra ingredientes e faz tudo. - PaaS = massa pronta + forno; você monta e assa. - SaaS = pizza pronta na porta.

  On-premises: você gerencia TUDO
  IaaS:  └────── você ──────┘ └── provedor ──┘
  PaaS:  └─── você ───┘ └────── provedor ──────┘

6. Deep Dive: EC2

Elastic Compute Cloud = servidores virtuais (VMs). Aluga capacidade, escolhe SO/tamanho, paga por hora/segundo.

Tipos de Instância

Família Foco Prefixo Usar pra
General Purpose Equilíbrio T, M Web/app padrão
Compute Optimized CPU C Batch, alta performance
Memory Optimized RAM R, X Banco, big data
Storage Optimized Disco (I/O) I, D Logs, data warehouse
Accelerated GPU P, G ML, gráficos

Gatilhos de palavra: "database"/"in memory" → Memory · "batch"/"high-performance" → Compute · "machine learning"/"graphics" → Accelerated · "balanced" → General.

Modelos de Preço (o mais cobrado)

Modelo Desconto Interrompe? Compromisso? Usar pra
On-Demand 0% Não Não Imprevisível, teste
Spot até 90% Sim Não Tolerante a interrupção
Reserved ~72% Não Sim (1-3 anos) Previsível
Savings Plans ~72% Não Sim ($/h) Previsível + flexível
Dedicated Hosts — Não — Compliance/licença

Spot = barato mas pode cair · On-Demand = estável, preço cheio · Reserved = desconto, exige compromisso.

Interrupção do Spot

  • Não é global da região — é por pool (AZ × tipo de instância).
  • Motivo: AWS precisa da capacidade de volta. Aviso: ~2 min antes.
  • Mitigação: múltiplas AZs + múltiplos tipos + hibernar.

Auto Scaling vs ELB

Auto Scaling ELB
Função Cria/remove instâncias Distribui tráfego
Cria? Sim Não

ELB = porteiro (distribui) · Auto Scaling = RH (contrata/demite).

10. Deep Dive: SNS e SQS

SNS (notificação)

  • Pub/sub (push) — publica em tópico, envia pra muitos.
  • Subscribers: e-mail, SMS, push, HTTP, Lambda, SQS.
  • Não guarda mensagem (quem não ouvir, perde).

SQS (fila)

  • Fila (pull) — produtor coloca, consumidor puxa.
  • Guarda a mensagem (até 14 dias). Desacopla sistemas.
  • Standard (alto volume, pode duplicar/desordenar) vs FIFO (ordem garantida).

SNS vs SQS

SNS SQS
Modelo Push Pull
Entrega Um pra muitos Um pra um
Guarda? Não Sim
Uso Notificar Processar

O combo SNS → SQS

[Evento] → [SNS] → [SQS fila A] → Consumidor A
                 → [SQS fila B] → Consumidor B
                 → [SQS fila C] → Consumidor C

Broadcast (SNS) + garantia de entrega (SQS) = não perder mensagem.

11. Deep Dive: VPC e Rede

VPC = rede privada e isolada (o "terreno cercado" onde tudo mora).

Componentes

Componente Função
Subnet Subdivisão (pública = internet; privada = sem internet)
Internet Gateway Porta de saída pra internet
Route Table Mapa do tráfego
Security Group Firewall por instância (stateful, só allow)
Network ACL Firewall por subnet (stateless, allow+deny)

⚠️ Cada subnet fica em UMA AZ — espalhe em várias pra alta disponibilidade.

Segurança: SG vs NACL

Security Group NACL
Nível Instância Subnet
Estado Stateful Stateless
Regra Só allow Allow + deny

Personalização por regras da empresa

  • Banco nunca exposto → subnet privada + sem Internet Gateway.
  • Só TI acessa por SSH → SG libera porta 22 só pro IP do escritório.
  • Dados não passam pela internet → VPC Endpoint (EC2 → S3 privado).
  • Dev isolado de prod → VPC Peering (conecta 2 VPCs).
  • Bloquear um país → NACL com DENY por IP.

VPC vs outros

Serviço Função
VPC Rede privada
Route 53 DNS
CloudFront CDN
Direct Connect Conexão física dedicada

12. DNS e Route 53

DNS = a "agenda" que converte nome (domínio) em número (IP).

www.amazon.com  →  (DNS resolve)  →  205.251.242.103

Registros

Registro Faz
A Nome → IPv4
AAAA Nome → IPv6
CNAME Apelido → outro nome
MX Servidor de e-mail
TXT Texto/verificação

Route 53 = o DNS da AWS

  • Registra domínios, hospeda registros, roteia tráfego.
  • Usa Edge Locations → é global.
  • Nome "53" = porta padrão do DNS.

⚠️ Route 53 (resolve nome) ≠ CloudFront (entrega conteúdo) — ambos globais e usam Edge Locations.

A jornada de uma requisição (passo a passo)

  1. Route 53 converte o nome em IP.
  2. CloudFront serve conteúdo estático do cache (edge) mais próximo.
  3. Internet Gateway deixa o tráfego entrar na VPC.
  4. ELB distribui entre as instâncias EC2 (faz health check).
  5. Auto Scaling cria/remove instâncias conforme a demanda (em 2 AZs).
  6. EC2 processa; usa EBS (disco) e ElastiCache (cache).
  7. Banco guarda: RDS (relacional) / DynamoDB (NoSQL) / S3 (arquivo).
  8. Integração: SNS notifica, SQS enfileira, EventBridge roteia.
  9. Lambda roda tarefas curtas disparadas por evento (sem servidor).
  10. CloudWatch monitora, CloudTrail audita, Budgets controla custo.

O insight da prova: nenhum serviço trabalha sozinho — é um encadeamento, com IAM validando tudo em segundo plano.

16. Escolha de Região e AZ

Critérios pra AZ

  1. Alta disponibilidade (múltiplas AZs — nº 1)
  2. Latência (próximo do usuário)
  3. Custo (AZs têm preços diferentes)
  4. Capacidade (AZ com o tipo disponível)
  5. Compliance (dados em região específica)
  6. Restrição técnica (EBS/subnet são de 1 AZ)

Critérios pra Região

  • Compliance / residência (principal) · latência · preço · serviços disponíveis.
Conceito O que é Escolho por
Região Área geográfica Compliance, latência, preço
AZ Data centers isolados Alta disponibilidade
Edge Cache global Entrega rápida
